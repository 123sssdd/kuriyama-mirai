# 把 Hermes 恢复到一台新电脑

这份给乌萨奇或 Hermes 侧的栗山未来用：在新电脑上把 Hermes 跑起来，并恢复本机规矩。不要把仓库短版 soul.md 直接覆盖运行时 SOUL。不要把密钥写进仓库。

## 1. 先放好转轴

1. 安装并导入 Hermes，数据家放到该机的 Hermes home。在这台 Mini 上是 `/Users/mac/.hermes`；换机器时按实际用户名改路径，并同步改本目录里写死的路径。
2. 用 SSH 把私有仓 `123sssdd/kuriyama-mirai` 克隆到约定位置。在这台 Mini 上是 `/Users/mac/kuriyama-mirai`。
3. 读仓库 RESTORE.md，再读 SYNC.md，再读本目录 `本机规矩.md`。

## 2. 运行时文件怎么接

1. 本机 SOUL.md 不要用仓库 soul.md 整份覆盖。人设与心法按仓库 soul.md、persona.md 对齐；本机包装按 `运行时SOUL包装.md` 写回，四档案互不越界、开工必读、思考用中文、滴答与推送这些不要丢。
2. 四个档案的 `config.yaml` 里，把 `skills.create_dir` 和 `skills.external_dirs` 指到该机上的仓库 `skills/` 目录。
3. 把 `memory.memory_char_limit` 设为 40000（`user_char_limit` 保持 1375，除非另有新决定）。
4. 本机 MEMORY 按「本机层 + 仓库全本」注入：前面写该机路径与环境，后半段整份贴上仓库 `memory/MEMORY.md`。只动 MEMORY，不要把仓库 MEMORY 覆盖成运行时 SOUL。
5. Vertex 等凭证只放本机 `credentials/`，`.env` 改成该机路径，文件权限 600。仓库不存密钥。出网代理按该机实际情况写。
6. 会话工作目录要用该机的绝对路径。从 Windows 迁过来时，POSIX 不把 `C:\Users\...` 当成绝对路径，会导致会话恢复失败。

## 3. 网关与四个档案

1. 用官方方式安装并启动网关（这台 Mini 上是 launchd `ai.hermes.gateway`）。改配置后新开的会话才会读到新 MEMORY 和技能挂载。
2. 另外三个档案在 `~/.hermes/profiles/miku|bocchi|ray`。不要把栗山未来的人设 skill 强行加载给他们。仓库 `profiles/<id>/` 只是占位，他们自己或乌萨奇点名才往里迁。
3. 聊天背景图不在仓库里。若要恢复坐姿血玉背景，需要另行拷贝 `mirai-bg.webp` 给插件 kuriyama-wallpaper。

## 4. 对一下有没有漏

- 本机 SOUL 还在，而且没有被仓库短版覆盖。
- 本机 MEMORY 能看到仓库核心记忆，也保留该机路径。
- 四个档案都能找到仓库 `skills/`。
- 滴答口令只在环境变量里，聊天和仓库里都没有密钥。
- `git status` 干净，没有把 `.env` 或凭证提交上去。
