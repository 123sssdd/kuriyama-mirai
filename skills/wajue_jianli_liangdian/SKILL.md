# 挖掘简历亮点

把乌萨奇在工作和自建项目里遇到的一个有意思的点，挖成能写进简历、能在面试里讲深的亮点。由他本人于 2026-11-13 定下这套流程，首例见文末。

## 什么时候用

- 他说某件事「有意思」「想写进简历」「记一下这个点」；
- 一次排障、一次设计取舍、一个技术难点刚刚发生，细节还新鲜；
- 他在复盘某段经历，问「这个能不能当亮点」。

## 流程（六步）

1. **先把事实钉死**：时间线、现象、数据、结果，逐项核实再写。分清哪些是他本人做的、哪些是别人或系统做的；拿不准的地方明写「拿不准」，不许编、不许替他认领。排障类素材尤其要小心：截图和时间戳这类二手证据会骗人，能向当事人或日志核对的先核对。
2. **判断值不值得讲**：有没有真难点、有没有他的判断过程、有没有结果或数据、能不能对应目标岗位的能力（他的目标是 AI 全栈／Agent 工程师）。人设是亮点少而精，平庸的点宁可不收。
3. **做信息图集**：用手绘图和信息图 skills（首选 project-diagram-studio 的手绘纸面风；baoyu_infographic 备选）做一组图，帮他先建立故事线。固定五到六页：总览（这是什么事、为什么值得讲）、问题如何发现、问题是什么、排障过程、解决方案、复盘与进一步优化。图里中文多时不要让生图模型猜字，走可控的渲染路线保证文字准确；图做好逐页打开检查再交付。图集放 `~/workspace/your_files/简历亮点-信息图集/` 或该亮点自己的目录。
4. **起草面试问答（六段式）**：一、问题如何发现的；二、问题是什么；三、排障过程；四、解决方案；五、复盘；六、进一步优化。两条硬规矩：
- **解决方案只留 2–3 个最强亮点**，讲深讲透，不许堆满；
- **其余同样好的方法不要删，拆出来放进「进一步优化」**——哪怕现有方案已经是最佳实践，也把次优的好方法挪过去，因为「还能怎么做得更好」最能体现他的思考能力。复盘写方法论层面的收获（判断原则、排障习惯），不写流水账。
5. **给简历放置建议**：对照他当前简历的结构（实习经历／项目经历／专业技能）给一个明确建议和理由。原则：雇主项目只装雇主的工作，个人项目单开条目，不冒领；一个条目 1–2 条 bullet，一条讲背景与系统，一条讲难点与解法；技能栏已有覆盖的就不重复动。**简历原文默认不改，他说改才改**——本 skill 只给建议和草稿，不直接动简历文件。
6. **落成 todo**：写进滴答「简历亮点」清单（id `6aec23ebe4b0b0ea892d9840`），kind 用 CHECKLIST：desc 里放素材摘要、图集位置、放置建议、六段问答草稿，并带上图集图片和相关文件的链接（他的规矩：todo 要带相关图片和文件，方便点开理解；滴答接口不支持直接传附件，就把文件链接写进正文，原件路径也要写清；多图先合并成一份 PDF 只传一次，文件优先放他的 Google Drive 私有存放用长效链接，不用 48 小时过期的临时链接）；items 放他要亲手做的小步骤（看图集、定条目、写自己的说法、喊 Muse 追问）。这是他自己的 todo，只加说明和指导，**不替他勾完成**。

## 后续衔接（固定，不要跳步）

本 skill 到 todo 落地为止。之后等他先写出自己的版本，再：

1. 用 **grill-me** 向他追问，把六段逐段问深、问到边界；
2. 用【栗山未来·逐字稿】把讨论整理成稿（原话清单先行、只收最终复述、补充打标签）。

不要在本 skill 里替他把逐字稿写了，也不要把 Muse 的分析冒充他的答案。

## 反模式

- 把 Muse 的复盘和分析直接当成他的面试答案；
- 解决方案里塞五六个亮点，每个都讲不深；
- 把个人项目写进雇主实习经历里；
- 事实没核实就先做图、先写稿，错的事实会被图和稿一起放大；
- 图集文字交给生图模型自由发挥，中文糊成一片。
